## 1. 目标与验收标准

| 项 | 内容 |
|---|---|
| 目标 | 最小可用的登录 + 令牌鉴权，覆盖全部业务接口（`/api/**`），未认证返回 401 明确语义 |
| 验收标准 | ① 无令牌访问受保护接口 401；② 登录成功可访问业务接口；③ 错误口令 401；④ 前端登录/登出闭环可用；⑤ 令牌在双后端实例均有效 |
| 产出物 | 后端 `auth` 包（5 个类）+ `application.yml` 认证配置；前端登录页/路由守卫/令牌注入/401 回跳；`accept-s88.ps1`；本文件 |

## 2. 接口

| 接口 | 方法 | 说明 | 鉴权 |
|---|---|---|---|
| `/api/auth/login` | POST | 入参 `{username, password}`；返回 `token`、`tokenType`、`expiresAt`、`username`、`displayName`、`role` | **唯一白名单** |
| `/api/auth/me` | GET | 返回当前令牌对应用户与到期时间（前端刷新后恢复登录态） | 需令牌 |
| `/api/auth/logout` | POST | 把当前令牌 `jti` 写入吊销表，令牌立即失效（幂等） | 需令牌 |

错误语义：缺少/为空令牌 → 401「未认证：缺少访问令牌」；签名或有效期不过 → 401「访问令牌无效或已过期」；已登出 → 401「该访问令牌已退出登录」；登录参数缺失 → 400；口令错误 → 401「用户名或口令错误」（不区分用户不存在与口令错误，避免用户名枚举）。

## 3. 实现要点（详见报告 5.2.8）

1. **令牌方案**：`base64url(payload) + "." + base64url(HMAC-SHA256(payload))`，`payload = {sub, name, role, jti, exp}`；只用 JDK `javax.crypto`，**不引入 JWT 依赖**（规避构建期依赖下载）；签名用 `MessageDigest.isEqual` 常量时间比较。
2. **密钥与多实例**：`app.auth.secret`（环境变量 `AUTH_SECRET` 覆盖）；**双实例必须一致**，否则负载均衡下跨实例校验失败——这是本方案唯一的部署约束。
3. **鉴权链路**：`AuthInterceptor` 拦截 `/api/**`（白名单仅登录接口），次序为「Bearer 头 → 签名与有效期 → 吊销表」；`/actuator/health`、`/swagger-ui/**`、`/v3/api-docs` 不在 `/api/**` 前缀内天然放行；`OPTIONS` 预检放行。
4. **吊销表（MongoDB 集合 `auth_revoked`）**：`_id=jti`、`username`、`revokedAt`、`exp`（**TTL 索引**自动清理过期记录）。**必须落库而非进程内存**——后端双实例负载均衡下，内存黑名单会出现"在 A 实例登出、请求落到 B 仍有效"。
5. **前端闭环**：`/login` 独立全屏页；路由守卫（未登录回登录页并带 `redirect`）；axios 请求拦截统一注入 `Authorization: Bearer`；401 时清空本地登录态并跳回登录页；侧边栏显示当前用户 + 退出登录（先调后端吊销接口）。

```powershell
cd docker
```

手工验证：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/devices        # 401
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin123"}' | jq -r .token)
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/devices   # 200
curl -s -X POST -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/auth/logout
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/devices   # 401
```

## 7. 已知边界与简化（不夸大）

1. **只做"认证"，未做"授权"**：任何已登录用户可访问全部业务接口与维护接口，**未实现基于角色的细粒度授权（403）**；报告 5.2.8(3) 已明确 401/403 语义边界。
2. **账号为配置化，口令明文比对**：生产应改为用户表 + 加盐哈希（bcrypt/argon2）、登录失败次数限制、登录审计；演示口令经环境变量可覆盖，但默认值仍在配置文件中（课程仿真环境可接受）。
3. **令牌无刷新机制**：有效期 12 小时，到期需重新登录（未实现 refresh token）。
4. **吊销表随令牌自然过期**：TTL 与令牌 `exp` 对齐；已登出令牌在过期前始终被拒（符合预期）。
5. **传输安全**：演示环境为 HTTP，未启用 HTTPS/TLS；生产应置于 TLS 之后（令牌在明文信道上可被窃听）。
6. **Swagger "Try it out"** 需手工填入 `Authorization: Bearer <token>`（未在文档页内做登录集成）。
7. **Nginx 未使用 `auth_request`**：校验统一在后端（理由见报告 5.2.8(1)）；网关侧仅透传 `Authorization` 头。
